# KL-in-LLM-RL 训练环境配置指南

如果你习惯 conda 和 pip，可直接使用独立的 [Conda + pip 安装教程](Conda与pip训练环境安装教程.md)，无需安装 uv。

适用代码：本仓库 `8ff8a9f`；官方资料查询日期：2026-11-19。本文目标是配置本地修改版 verl 的 **NVIDIA GPU + Linux + FSDP + vLLM** 环境。它是依据代码与官方资料给出的安装和排查方案，尚未在当前 Windows 工作区执行 GPU 安装或训练。

## 1. 先区分本地 fork 与上游版本

搜索确认，上游是 [verl-project/verl](https://github.com/verl-project/verl)。上游 `main` 与 latest 文档持续更新；当前[官方安装页](https://verl.readthedocs.io/en/latest/start/install.html)已有基于新 `uv.lock` 的环境管理流程。本仓库没有对应的锁文件和管理脚本，不能照搬 `uv sync --frozen --extra fsdp` 等新上游命令。

本地版本文件是 `0.8.0.dev`，但这不是精确上游 commit 标识。本仓库是整份源码内置于 `verl/`，而非运行前必须另克隆的依赖。必须安装这里的源码，才能使用 `prm`、`prl_current_kl`、KL 修正等定制功能。

| 本地证据 | 约束 / 问题 |
| --- | --- |
| `verl/pyproject.toml` | Python >=3.10 |
| `verl/setup.py` | numpy<2；pyarrow>=19；Ray>=2.41；tensordict>=0.8,<=0.10 且排除 0.9 |
| `verl/setup.py` 的 vllm extra | vLLM>=0.8.5,<=0.12.0 |
| `verl/scripts/install_vllm_sglang_mcore.sh` | 安装 vLLM 0.11.0；FlashAttention 2.8.1；FlashInfer 0.3.1；示例 wheel 对应 Python 3.12 / torch 2.8 |
| `verl/docs/start/install.rst` | 此份本地指南要求 CUDA>=12.8，推荐 Python 3.12 |
| 原提交的 `rl-kl/*.sh` 首部注释 | 曾声称使用 torch2.6 / vLLM0.8.4 镜像；0.8.4 低于本地 extra 下限，该过时注释已移除 |
| 本地 `Dockerfile.stable.vllm` | 使用更高版本 vLLM，超出 setup.py 上限；不能直接当作匹配本实验的环境锁定文件 |

据此，本文选择 **Python 3.12 + vLLM 0.11.0 + PyTorch 2.8.0 + CUDA 12.8 系列 + FlashAttention 2.8.1** 作为候选组合；这是本地脚本指向的组合，不是已验证复现环境。vLLM 0.11.0 的官方[CUDA 依赖文件](https://github.com/vllm-project/vllm/blob/v0.11.0/requirements/cuda.txt)明确锁定 torch 2.8.0、torchaudio 2.8.0、torchvision 0.23.0。

## 2. 主机准备与 Windows 用户的工作方式

建议在 Linux GPU 服务器上运行训练，在 Windows 上编辑代码。WSL2 可以作为另一个 Linux 执行环境，但其 GPU、Docker 和多卡通信需要单独验证；本文不假设原生 PowerShell 可以直接运行训练栈。vLLM GPU 支持与系统要求见[该版本官方安装说明](https://docs.vllm.ai/en/v0.11.0/getting_started/installation/gpu.html)。

在 Linux 主机检查：

```bash
nvidia-smi
nvidia-smi topo -m
df -h
free -h
```

需要可用 NVIDIA 驱动、适配所选 CUDA runtime 的 GPU、足够的主存和磁盘。`nvidia-smi` 的 CUDA Version 表示驱动支持能力，不等同已安装的 toolkit；源码编译 FlashAttention 还要检查 `nvcc --version`。GPU 型号未知，无法保证显存需求；默认脚本是 32 卡、长回答配置，单卡先缩短长度测试。

### 方案 A：Docker 隔离运行

先在宿主机安装 Docker 和 NVIDIA Container Toolkit，确认 `docker run --rm --gpus all ... nvidia-smi` 可用。上游[安装文档](https://verl.readthedocs.io/en/latest/start/install.html)支持使用预置镜像再安装本地源码；这里选固定 vLLM 版本，避免随 `latest` 漂移。

```bash
# 宿主机：从本仓库根目录执行
export REPO_ROOT="$PWD"
docker pull vllm/vllm-openai:v0.11.0
docker run --rm -it --gpus all --ipc=host \
  --entrypoint /bin/bash \
  -v "$REPO_ROOT:/workspace/KL-in-LLM-RL" \
  -v "$HOME/.cache/huggingface:/root/.cache/huggingface" \
  -w /workspace/KL-in-LLM-RL \
  vllm/vllm-openai:v0.11.0
```

镜像标签的当前可拉取性和镜像内完整包清单未实测。vLLM 基础镜像不代表包含全部训练依赖，进入后仍执行第 3 节。需要从源码编译 FlashAttention 时，若镜像没有 nvcc/开发头文件，改用 CUDA 12.8 的 **devel** Linux 基础镜像并走方案 B，或使用与 torch/Python/CUDA/ABI 完全一致的官方 wheel。多机还需要在可信集群网络中配置容器网络与 Ray/NCCL 互通。

### 方案 B：已有 CUDA 开发环境的 Linux 主机

系统需有 Python 3.12、git、C/C++ 编译工具、CUDA toolkit 开发组件。项目级虚拟环境使用 `uv` 管理。若 uv 未安装，按其安装器安装后重新打开 shell：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

在 Linux 工作盘获取本仓库；若已经同步了代码，不要再次克隆覆盖：

```bash
git clone https://github.com/ScaleML/KL-in-LLM-RL.git
cd KL-in-LLM-RL
git rev-parse HEAD
```

## 3. 安装 Python 环境与本地 verl

以下从仓库根目录执行；Docker 也使用相同流程，`--system-site-packages` 用于复用镜像内匹配的计算库。不要同时安装 SGLang / Megatron extras：本实验只需要 FSDP + vLLM。

```bash
uv venv --python 3.12 --system-site-packages .venv
source .venv/bin/activate
python --version

# 先安装推理框架，让它选择匹配的 torch
uv pip install 'vllm==0.11.0'

# 约束关键计算栈，避免后续安装悄悄替换
cat > constraints-local.txt <<'EOF'
torch==2.8.0
torchaudio==2.8.0
torchvision==0.23.0
vllm==0.11.0
numpy<2.0.0
transformers>=4.51.0,<5
pyarrow>=19.0.0
tensordict>=0.8.0,<=0.10.0,!=0.9.0
EOF

cd verl
uv pip install -c ../constraints-local.txt -e '.[math]' \
  'transformers>=4.51.0,<5' 'flashinfer-python==0.3.1' \
  latex2sympy2_extended liger-kernel ninja packaging wheel setuptools
```

`transformers<5` 是针对该旧栈的保守兼容约束，并非本地 setup.py 的硬性要求；最终小版本需要通过下面的模型和训练预检确认并锁定。`.[math]` 安装本地源码与 Math-Verify；不要在随后执行上游 `pip install verl`，否则可能导入错误实现。

默认脚本开启 remove padding，需要 FlashAttention。先检查已有包：

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda, torch._C._GLIBCXX_USE_CXX11_ABI)"
python -c "import flash_attn; print(flash_attn.__version__)"
```

若缺包，在有匹配 CUDA 编译工具的环境中执行：

```bash
nvcc --version
MAX_JOBS=4 uv pip install -c ../constraints-local.txt \
  'flash-attn==2.8.1' --no-build-isolation
```

编译过程可能下载或构建 wheel。仓库安装脚本的 FlashAttention wheel 写死 `cxx11abiFALSE`，不能只因 torch 版本相同就套用；必须核对 ABI、Python、平台和 CUDA。若环境里已有不同版本 flash_attn，先验证其兼容性，记录实际版本，勿把“可导入”当作 kernel 运行通过。

不建议直接运行整个 `install_vllm_sglang_mcore.sh`：它默认还装 SGLang、Megatron 和多个与本次无关的组件，且部分依赖与 setup.py 版本不一致。FSDP 路径通常无需 Apex、TransformerEngine、Megatron、DeepEP。

## 5. 下载模型并检查 tokenizer 模板

在 `verl/` 下设置绝对目录（每台节点使用相同路径）：

```bash
export DATA_ROOT="$PWD"
export MODEL_PATH="$DATA_ROOT/models/Qwen3-1.7B-Base"
export TRAIN_FILE="$DATA_ROOT/data/dapo_filter.parquet"
mkdir -p "$DATA_ROOT/data/math500" "$DATA_ROOT/models"
python - <<'PY'
import os
from huggingface_hub import snapshot_download
snapshot_download('Qwen/Qwen3-1.7B-Base', local_dir=os.environ['MODEL_PATH'])
PY
```

先确认聊天模板：

```bash
python - <<'PY'
import os
from transformers import AutoTokenizer
t = AutoTokenizer.from_pretrained(os.environ['MODEL_PATH'])
print('has chat template:', bool(t.chat_template))
if t.chat_template:
    print(t.apply_chat_template([{'role': 'user', 'content': '1+1=?'}],
                                tokenize=False, add_generation_prompt=True))
PY
```

Base 模型不能假设一定带 chat template。若缺失，训练数据过滤与 rollout 都可能失败。应使用论文/原实验确定的模板；若只是连通性试跑，可在**本地下载副本**写入一个简单模板：

```bash
python - <<'PY'
import os
from transformers import AutoTokenizer
p = os.environ['MODEL_PATH']
t = AutoTokenizer.from_pretrained(p)
if not t.chat_template:
    t.chat_template = "{% for m in messages %}{{ m['content'] }}{% endfor %}{% if add_generation_prompt %}{{ '\\n' }}{% endif %}"
    t.save_pretrained(p)
    print('已给本地 tokenizer 写入试跑模板')
PY
```

这个简化模板不是论文复现模板。正式实验需统一训练与评测模板并保存记录。模型名与路径分别控制实验标签和实际载入模型：脚本中的 `MODEL_NAME` 固定，覆盖 MODEL_PATH 后实验名可能仍显示原模型。

## 6. 准备训练与验证 Parquet

根 README 给出[训练集](https://huggingface.co/datasets/FlippyDora/dapo-filter)和[math500 验证集](https://huggingface.co/datasets/CorrectKLinRL/math500)。本次网络工具未成功读取这两个数据集页面，所以不声称已核实在线 schema 和 split；下面代码会打印实际结构并在不匹配时停止。

在 `verl/` 下创建并运行一次性准备脚本：

```bash
cat > prepare_local_data.py <<'PY'
import os
from pathlib import Path
from datasets import load_dataset

root = Path(os.environ['DATA_ROOT']) / 'data'
for repo, split, out, source in [
    ('FlippyDora/dapo-filter', 'train', root/'dapo_filter.parquet', 'dapo_filter'),
    ('CorrectKLinRL/math500', 'test', root/'math500'/'test.parquet', 'math500'),
]:
    splits = load_dataset(repo)
    print(repo, splits)
    if split not in splits:
        raise ValueError(f'{repo} 缺少 {split} split；请按实际数据结构选择，不能自动拿训练集当验证集')
    ds = splits[split]
    print('columns:', ds.column_names)
    print('example:', ds[0])
    if not {'prompt', 'reward_model'}.issubset(ds.column_names):
        raise ValueError('需要先映射为 prompt 消息列表与 reward_model.ground_truth；参见代码说明第 4 节')
    def normalize(row, idx):
        prompt = row['prompt']
        if not isinstance(prompt, list) or not prompt or not isinstance(prompt[0], dict):
            raise ValueError('prompt 应是非空消息列表，不是原始字符串')
        gold = row['reward_model']['ground_truth']
        if gold is None:
            raise ValueError('ground_truth 不能为空')
        return {'prompt': prompt, 'data_source': source, 'ability': 'math',
                'reward_model': {'style': 'rule', 'ground_truth': str(gold)},
                'extra_info': {'index': idx, 'split': split}}
    ds = ds.map(normalize, with_indices=True, remove_columns=ds.column_names)
    out.parent.mkdir(parents=True, exist_ok=True)
    ds.to_parquet(str(out))
    print('saved:', out, 'rows:', len(ds))
PY
python prepare_local_data.py
```

若在线数据只有 `problem` / `answer` 等原始列，按实际列名替换 `normalize`，构造说明文档中的统一结构，不能把列名猜测当作已经转换成功。统一 `data_source` 是为了命中本仓库的 Math-Verify 路由；ground_truth 应为原始最终答案，避免重复包装 `\boxed{}`。正式复现还应核对原数据的 scoring 语义。

准备好后，先验证奖励链路：

```bash
python -c "from verl.utils.reward_score import default_compute_score; score = default_compute_score('dapo_filter', r'\boxed{2}', '2'); print('score:', score); assert score == 1.0, '检查 Math-Verify 安装与子进程错误'"
```

此测试使用 `python -c`，避免把需要 spawn 子进程的验证调用放在 `python -` 标准输入脚本中，导致子进程找不到主文件。

## 7. 单机最小训练试跑

以下示例在 `verl/` 下使用单卡、短上下文、小 batch 跑 2 步，主要检查数据→生成→奖励→actor 更新→保存是否打通。它改变了实验规模与长度，不用于报告论文指标。显存是否足够仍取决于实际 GPU。

```bash
export DATA_ROOT="$PWD"
export TRAIN_FILE="$DATA_ROOT/data/dapo_filter.parquet"
export MODEL_PATH="$DATA_ROOT/models/Qwen3-1.7B-Base"
export CKPTS_DIR="$DATA_ROOT/ckpts/smoke-grpo"
export MAX_PROMPT_LENGTH=1024 MAX_RESPONSE_LENGTH=512
export ROLLOUT_TP=1 ROLLOUT_N=2 VAL_N=1
export PPO_MINI_BATCH_SIZE=2
export PPO_MICRO_BATCH_SIZE_PER_GPU=1 LOG_PROB_MICRO_BATCH_SIZE_PER_GPU=1
export ROLLOUT_GPU_MEMORY_UTILIZATION=0.4 ROLLOUT_MAX_NUM_SEQS=4
export OFFLOAD=True

set -o pipefail
bash rl-kl/train.sh \
  "data.val_files=['$DATA_ROOT/data/math500/test.parquet']" \
  data.train_batch_size=2 data.train_max_samples=16 data.val_max_samples=2 \
  data.filter_overlong_prompts_workers=2 \
  trainer.nnodes=1 trainer.n_gpus_per_node=1 \
  trainer.total_training_steps=2 trainer.total_epochs=1 \
  trainer.val_before_train=False trainer.test_freq=-1 trainer.save_freq=2 \
  trainer.experiment_name=smoke-grpo 'trainer.logger=[console]' \
  actor_rollout_ref.rollout.enforce_eager=True \
  2>&1 | tee smoke-grpo.log
```

如过滤后样本不足一个 batch，增加 `train_max_samples` 或 prompt 上限，不能把“没有报 CUDA 错”当成完成了更新。第一次试跑关闭预验证，避免默认每题采样 16 次造成长时间等待。`enforce_eager` 可降低 CUDA graph 捕获的额外显存。

验收标准：进程正常退出、确实有两步更新日志、reward 不全是解析异常、loss/grad norm 有限、保存目录出现 `global_step_2/actor`。然后另开一个短验证任务检查验证链路。

### 切换 PRM 与 current-policy PRL

保留以上小规模参数，把脚本改成 `train_prl.sh` 即可测 PRM。每次使用单独 CKPTS_DIR 和 experiment_name，避免 `resume_mode=auto` 意外恢复别的实验。

current-policy PRL 则改成 `train_prl_current_policy.sh`，建议显式保留总配置已有的默认值：

```bash
trainer.use_legacy_worker_impl=disable
```

总配置已经是 `disable`，无需修复默认入口。需要强调此值，是因为若人为改成 `auto/enable`，旧 `dp_actor.py` 没向 `prl_current_kl` 传参考 log-prob，而新 `workers/utils/losses.py` 已接好；详见[代码说明第 7 节](代码实现与训练说明.md)。此结论来自静态检查，未做端到端 GPU 验证。PRM 使用 `prm.eta`，current-policy 使用 `actor_rollout_ref.actor.policy_loss.prl_eta`；两者不是同一配置字段。

正式训练再逐步恢复 2048/8192 长度、rollout.n=5、val n=16、大 batch 和真实 GPU 数。此前导出的 MAX_* 等环境变量会继续影响脚本，恢复实验时务必重新设置；10240 token 长度可能显著增加显存与耗时。

## 8. 单机多卡与四节点配置

单机 8 卡可设 `ROLLOUT_TP=4`，追加 `trainer.nnodes=1 trainer.n_gpus_per_node=8`。rollout TP 应适配可用 GPU 拓扑和模型注意力头数；训练 FSDP 与生成 TP 是不同并行维度。batch、rollout 数和数据并行数须满足 worker 的拆分要求，遇到整除断言应按最终配置计算。

多节点不能只设置 `trainer.nnodes=4`：必须先启动 Ray 集群。所有节点的源码、Python 环境、模型和数据路径要一致；checkpoint 路径应共享或明确保证各 rank 文件可归集。[官方多机文档](https://verl.readthedocs.io/en/latest/start/multinode.html)说明了 head/worker 加入与状态检查流程。

```bash
# head：替换为实际 head 内网地址；每个节点先激活同一环境
export HEAD_IP=10.0.0.10
ray start --head --node-ip-address="$HEAD_IP" --port=6379 --num-gpus=8

# 其余三个 worker 节点分别执行
export HEAD_IP=10.0.0.10
ray start --address="$HEAD_IP:6379" --num-gpus=8

# head 上确认共 4 节点、32 GPU
ray status
```

从 head 的 `verl/` 目录启动一次 driver：

```bash
bash rl-kl/train_prl.sh \
  "data.val_files=['$DATA_ROOT/data/math500/test.parquet']" \
  trainer.nnodes=4 trainer.n_gpus_per_node=8 \
  +ray_kwargs.ray_init.address=auto
```

这里用 `+` 是因为本地 Hydra 配置未预声明 `ray_init.address`。不要在每个节点各启动一份完整 trainer。Ray 服务只放在可信集群网络；容器网络、NCCL 网卡选择和节点间通信必须匹配实际集群，不应盲目复制别人机器的 `NCCL_SOCKET_IFNAME`。

## 9. 日志、导出、评测与恢复

训练脚本已默认启用 console + SwanLab，并通过 `setup_logging.sh` 检查 SDK 与设置日志目录。需另安装 swanlab 并先运行 `swanlab login`，或设 `SWANLAB_LOGIN=1` 在启动时交互登录。首次连通测试可设 `TRAINER_LOGGER='[console]'` 或追加 `'trainer.logger=[console]'`。脚本不再开启 shell 命令跟踪，也不覆盖 WANDB_ENTITY；需要 W&B 时可设 `TRAINER_LOGGER='[console,wandb]'` 并自行登录。

```bash
# 在 verl/ 下导出试跑 checkpoint
python -m verl.model_merger merge --backend fsdp \
  --local_dir "$CKPTS_DIR/global_step_2/actor" \
  --target_dir "$DATA_ROOT/models/smoke-merged"

# 回到仓库根目录运行评测
cd ..
python eval/eval.py --model "$DATA_ROOT/models/smoke-merged" \
  --data "math500=$DATA_ROOT/data/math500/test.parquet" \
  --output-dir eval/results --output-name smoke-math500 \
  --n 1 --max-response-length 512 --max-model-len 1536 --tp 1 --dp 1
```

上述评测只是连通性验证，短上下文不会复现完整数学基准指标。恢复训练时用原保存目录和 `trainer.resume_mode=auto`；若指定 checkpoint，使用 `resume_mode=resume_path` 与 `resume_from_path`。保存/导出/完整评测的更多细节见[代码实现与训练说明](代码实现与训练说明.md)。

## 10. 常见问题与定位顺序

| 现象 | 优先检查 |
| --- | --- |
| `Unknown advantage estimator prm` / 无 PRL loss | `verl.__file__` 是否指向本地源码；是否误装上游包 |
| `prl_current_kl loss requires ref_log_prob` | 使用新 worker override；旧 actor 未接该参数，单独调 KL 系数无法修复 |
| `undefined symbol` / flash_attn 导入失败 | torch、CUDA、Python、CXX11 ABI 是否与 wheel 匹配 |
| `No module named math_verify` 或奖励几乎总是 0 | 安装 `.[math]`；运行标准答案测试并检查 spawn 子进程异常 |
| `Reward function is not implemented for ...` | Parquet 的 `data_source` 是否在本地评分路由内 |
| `Cannot use chat template` | Base 模型 tokenizer 是否包含模板；训练和评测是否一致 |
| 找不到数据 / 模型 | DATA_ROOT 用绝对路径；TEST_FILE 被写死，必须另覆盖 `data.val_files` |
| Ray 一直等待资源 | 默认 4×8 配置是否改过；`ray status`；容器可见 GPU 与每节点数量 |
| vLLM KV cache / CUDA OOM | 先降 response 长度、max_num_seqs、采样数；再调 memory utilization、token budget；它们的作用不同 |
| actor 更新 OOM | 减 token budget、mini batch，确认 gradient checkpointing 与 offload；单条序列本身过长时仅减 micro batch 无效 |
| 预训练验证很慢 | 默认 val_before_train=True、val n=16；先缩小验证样本和 n |
| 新装依赖后不能运行 | 对比 freeze；检查 torch/vLLM/transformers 是否被替换 |
| 数据准备 schema 断言 | 查看实际列与 split，显式映射；不要无条件改名后继续训练 |
